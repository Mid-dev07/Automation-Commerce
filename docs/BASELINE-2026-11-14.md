## 1. Cakupan dan sumber

Repository ini adalah source backend utama untuk Worker pemesanan Telegram Seiton.id:
- `worker.js`: webhook Telegram, katalog, checkout, verifikasi pembayaran, admin.
- `transaction-layer.js`: transaksi D1 dan koordinasi stok.
- `messaging-core.mjs`: pemrosesan pesan dan handoff.
- `digital-products.mjs`: inventori akun digital, fulfillment, dan onboarding.
- `otp-portal/`: source Worker portal mailbox.
- `site-admin/`: source Worker panel pemilik dan API harga.
- `migrations/`: migrasi D1 dan audit.
- `tests/`: regression dan contract tests.

Repository terpisah `midznight/seiton.id` berisi website Astro, dokumentasi Worker, dan sebagian migrasi; repository ini tidak berisi seluruh source Worker proprietary yang sedang berjalan di Cloudflare.

## 4. Produk digital — keadaan saat audit

SKU D1:
- `MUSE-STARTER`: Rp25.000, stock 0, inactive.
- `MUSE-BISNIS`: Rp150.000, stock 0, inactive.
- `OTP-SETUP`: Rp100.000, stock NULL, inactive.

Tidak ada entri stok digital atau fulfillment aktif pada snapshot agregat yang diperiksa. Jangan mengaktifkan produk atau memasukkan kredensial sebelum alur email/portal lolos QA.

Guardrail kode:
- Akun disimpan terenkripsi AES-GCM dengan secret `MUSE_STOCK_ENCRYPTION_KEY`.
- D1 adalah sumber kebenaran inventori; Durable Object menyerialisasi operasi per SKU.
- `MUSE_KV` hanya cache/summary, bukan lock stok.
- `OTP_EMAIL_ROUTING_READY` default `false`; penambahan stok, pembuatan link portal, dan pengiriman digital ditahan sampai kesiapan routing dinyatakan benar.
- Produk baru dimasukkan ke katalog Telegram hanya jika aktif.
- Data kredensial pelanggan/stok tidak boleh dicetak ke log atau dokumentasi.

**Catatan arsitektur:** dokumen master awal menyebut KV sebagai tempat stok. Implementasi sekarang memakai D1 untuk inventori transaksional dan KV untuk cache. Ini lebih sesuai kebutuhan atomicity/consistency, tetapi merupakan keputusan arsitektur yang perlu diselaraskan secara eksplisit di dokumen master sebelum fase berikutnya.

## 6. Temuan drift source-of-truth — blocker sebelum deploy

1. `wrangler.toml` root adalah konfigurasi legacy yang hanya memuat Worker utama dan Google Sheets; `wrangler.jsonc` lebih baru tetapi belum mencerminkan seluruh binding production.
2. `wrangler.jsonc` backend tidak mencantumkan binding R2 `PRODUCT_MEDIA` yang ada di production.
3. Source OTP portal di repository hanya mendeskripsikan binding `OTP_KV`; production juga memakai `MAILBOX_INDEX`, `MUSE_KV`, `OTP_ALLOWED_DOMAINS`, dan `OTP_INTERNAL_SECRET`.
4. Production site-admin memiliki service binding `OTP_BACKEND` dan secret internal yang belum tercermin pada konfigurasi source repository.
5. Scan read-only atas source Worker production tidak menemukan referensi runtime `PRODUCT_MEDIA` atau `order_items`, meskipun binding R2 dan tabel multi-item ada. Fitur upload media dan checkout multi-item tidak boleh dianggap aktif hanya berdasarkan keberadaan binding/tabel; perlu rekonsiliasi source dan smoke test.
6. Migrasi `0002_multi_item_cart.sql` berada di repository lain, sehingga urutan migrasi belum terdokumentasi secara konsisten.

**Larangan operasional:** jangan deploy source repository ini ke Worker production sebelum source runtime, bindings, migrations, dan fitur yang benar-benar aktif direkonsiliasi. Jangan menjalankan migrasi production atau mengubah secret/binding dalam fase baseline.

## 7. Gerbang kesiapan sebelum fase implementasi

- Ekspor dan simpan source runtime ketiga Worker sebagai baseline yang dapat direproduksi.
- Bandingkan source runtime dengan repository dan rekonsiliasi perbedaan tanpa mengubah perilaku.
- Satukan seluruh migrasi D1 ke satu urutan yang dapat diaudit.
- Tambahkan test integrasi untuk cart multi-item, R2 media, digital fulfillment, portal OTP, dan site-admin OTP binding.
- Verifikasi Email Routing, domain fallback, ownership mailbox, dan end-to-end email sebelum mengubah `OTP_EMAIL_ROUTING_READY`.
- Pertahankan semua SKU digital nonaktif sampai stok dan portal lolos QA.
